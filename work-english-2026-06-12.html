Code Review & Technical Feedback
Word of the Day
regression /rɪˈɡreʃ.ən/
回归问题；功能退化
A regression is a bug introduced by a new change that breaks something that was previously working. In code review, catching regressions early is one of the most important goals.
This PR looks good, but I want to make sure it doesn't introduce a regression in the login flow.
We caught a regression in the notification system after the last deploy — rolling back now.
Sentence Patterns
"Did you run the tests to check for regressions?"
代码审查 · PR 评论
你跑测试检查有没有回归问题了吗？
Did you run the tests to check for regressions? The auth module is pretty sensitive.
Before we merge, did you run the tests to check for regressions in the payment flow?
"This could be a regression — ___ used to work differently."
代码审查 · Bug 讨论
这可能是个回归问题——之前…的行为不是这样的
This could be a regression — the dropdown used to work differently before the refactor.
This could be a regression — error messages used to be localized, but now they're in English only.
"Can we add a test to prevent this regression from coming back?"
代码审查 · 测试覆盖
能加个测试防止这个问题以后再出现吗？
Can we add a test to prevent this regression from coming back? It's the third time we've hit this.
Can we add a test to prevent this regression from coming back before we close the ticket?
Mini Scenario
You're reviewing a teammate's PR that touches the search feature. You notice something off in the results ranking.

"Hey, I think regression might be happening here — the relevance sorting used to prioritize exact matches, but now it seems to rank by recency instead. This could be a regression — the ranking logic used to work differently before the indexing refactor. Can we add a test to prevent this regression from coming back? Maybe a snapshot test on the top 3 results for a known query? Did you run the tests to check for regressions in the search module specifically?"
Quick Tip
💡
In English code reviews, framing a potential regression as a question ("Did you check for regressions?") rather than a statement ("This is a regression") sounds more collaborative and less accusatory. It gives your teammate a chance to say "yes, I tested it" — and if they didn't, they'll realize it themselves. This tone shift makes a big difference in team culture, especially in async reviews where there's no body language to soften the message.
