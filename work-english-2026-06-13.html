Code Review & Technical Feedback
Word of the Day
nit /nɪt/
小问题；细枝末节的挑剔
A minor, low-priority comment in a code review — something worth noting but not blocking. Short for "nitpick." Saying "just a nit" signals that your feedback is optional and the reviewer shouldn't hold up the PR over it.
This is just a nit, but the variable name could be more descriptive — maybe userCount instead of n.
I left a few nits in the comments, but overall the logic looks solid — LGTM.
Sentence Patterns
"Just a nit, but ___."
代码审查 · PR 评论
小问题，不影响合并，随你决定要不要改
Just a nit, but this function is getting a bit long — might be worth splitting it out.
Just a nit, but the comment here is outdated — the logic changed in the last refactor.
"Have you considered ___?"
代码审查 · 技术讨论
你有没有考虑过……（提建议而不是直接否定）
Have you considered using a map here instead of a nested loop? It would be O(n) instead of O(n²).
Have you considered what happens when the list is empty? That edge case might throw.
"This is a trade-off between ___ and ___."
技术讨论 · 架构评审
这是……和……之间的权衡（用来解释设计决策，而不是道歉）
This is a trade-off between readability and performance — I went with the clearer version since this path isn't hot.
This is a trade-off between flexibility and simplicity; we can always make it configurable later if needed.
Mini Scenario
You're reviewing a teammate's PR for a new API endpoint. The code works, but you spot a few things worth mentioning.

"Hey, overall this looks great — LGTM from a logic standpoint. Just a nit, but the error message on line 42 is a bit vague; something like 'User not found' would be easier to debug. Also, have you considered caching the DB call here? It's called on every request. This is a trade-off between latency and memory, but given the read frequency it's probably worth it. Happy to discuss if you want to sync."
Quick Tip
💡
In English-speaking engineering teams, code review comments are often prefixed with labels to set expectations: nit: (minor, optional), suggestion: (take it or leave it), question: (I'm curious, not blocking), blocker: (must fix before merge). Using these labels makes your intent immediately clear and reduces back-and-forth. "Nit: rename this variable" lands very differently from an unlabeled comment that might read as a hard requirement.
